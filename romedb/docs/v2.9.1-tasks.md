# RomeDB 2.9.1: Turso 0.8.3 engine

User-authorized 2026-10-20: release the merged Turso 0.8.3 engine sync
(romedb/romedb#30) as a patch release, then move RomeDB Cloud to it. 2.9.0 is
already published and stays immutable. Linux x64; all seven native clients. The
catalog format and stored data are unchanged.

## Engine

- [x] Turso 0.8.3 (`607bff9fd0e547a25a97b3bf06e83bcc5d99d53c`): MVCC durability
  fixes, AUTOINCREMENT no longer reuses an explicit id 1, and `PRAGMA journal_mode`
  refuses MVCC switches inside a transaction. All eight engine exceptions kept.
  See [the sync notes](turso-0.8.3.md) and [checklist](turso-0.8.3-tasks.md).

## Release

- [x] Version alignment: nine crates, Node, Python, PHP and C# packages, notices,
  upgrade table row 2.9.0 → 2.9.1.
- [x] Notices and RustSec review (359 shipping packages, zero unresolved findings).
- [x] Full scoped checks on the version-aligned source (1,104 Rust, 191 Node/application,
  five C ABI, two release-policy and three upgrade-table tests).
- [x] Upgrade dry run (15 checks on Node 22 and 24), exact-source CI, production
  bundle and all 49 installed verification groups, including 2.9.0 → 2.9.1.
- [x] Release records and tag `fastdb-v2.9.1` on the build commit `364091ab9`.
- [x] Publication and independent download verification ([receipt](release-2.9.1-download.json)).

## Cloud

- [x] Cloud runtime on the 2.9.1 engine in all three locations (Worker `10db013e`,
  2026-10-20; private record `docs/engine-2.9.1-cloud.md` in romedb/cloud#38).
  Metering is unchanged. Inserts into `AUTOINCREMENT` tables ended the Cloud MVCC
  owner on 2.9.0 and on the first 2.9.1 rollout; the engine is correct. The Cloud
  runtime fix shipped on 2026-10-20 (romedb/cloud#39), and DDL beside concurrent
  writes was fixed on 2026-10-21 (romedb/cloud#40), both on this engine.
